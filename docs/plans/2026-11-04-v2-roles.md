## 已实测的事实（0.166.0）

- `codex exec --json` 输出 JSONL：`item.completed` 的 `item.type == "agent_message"` 带 `text`；`turn.completed` 带 `usage`，字段是 `input_tokens`、`cached_input_tokens`、`cache_write_input_tokens`、`output_tokens`。配置警告以 `item.type == "error"` 出现，不代表失败。
- 提示可以从 stdin 传，参数写 `-`。
- `--disable shell_tool` 后模型没有 shell。
- MCP 进程环境是白名单：`HOME LANG LC_ALL LOGNAME PATH SHELL TERM USER`，加 `.mcp.json` 的 `env_vars` 列出的变量。
- `.mcp.json` 支持 `tool_timeout_sec`、`default_tools_approval_mode: "approve"`、`env_vars`、`"cwd": "."`。
- `_meta` 带 `sessionId`、`codex/sandbox-state.sandboxCwd`（`file://` URI）、`codex/sandbox-launcher.codexExecutable`。
- hook 被 `SIGKILL`，`runProcess` 的看门进程负责清理子进程组。这对角色子进程同样有效。

## 设计

### 配置

`.cw/project.toml` 的 schema 不变。新增 `.cw/codex.toml`，可选：

```toml
[models]                 # 六个角色，Codex 模型 slug，非空且不含空白
review = "gpt-5.6-terra"

[roles]
sandbox = "read-only"    # 或 "none"，缺省 read-only
```

`additionalProperties: false`。`project.toml` 的 `[models]` 在 Codex 下忽略。`ProjectConfig` 增加 `models`、`timeouts`、`auto`、`router`、`sandbox`，去掉 `autoRequested`。

- `codex.toml` 非法：与 `project.toml` 非法同样处理，检查和保护都停，`SessionStart` 和 `Stop` 显示错误。
- `[auto]` 打开但 `codex.toml` 没配对应模型：**不算配置错误**，这一项视为关闭，`SessionStart` 提示。这与 pi 版不同，原因是共用文件里合法的 `[auto]` 不能让 Codex 的检查和保护失效。
- `isProtected` 同时保护 `.cw/codex.toml`。

### 回合状态

新模块 `src/core/turnstate.ts`，目录 `$PLUGIN_DATA/sessions/<session_id>/`，`session_id` 含路径分隔符或 `..` 时视为不可用。

- `claim(session, turn, name)`：用 `open(path, "wx")` 原子创建标记，首次返回 true。名字有 `repair`、`findings`、`pause`。任何文件系统错误返回 false，也就是不续跑、不拦截。
- 用户原话由 `UserPromptSubmit` 写入 `<turn_id>.prompt`，读不到时用空串。
- `SessionEnd` 删除整个 session 目录。崩溃残留可接受。

`Stop` 不再用 `stop_hook_active`，改用 `repair` 标记，因为检查续跑和审查续跑要分开计数，与 pi 版的两份额度一致。

### 角色子进程

`src/roles/run.ts`，移植 pi 版的超时规则（`clampTimeoutS`、`nextTimeoutS`、默认值），换掉 CLI 查找和参数：

```text
<codex> exec --json --ephemeral --skip-git-repo-check
  --disable hooks --disable plugins
  -m <model> -c developer_instructions=<JSON.stringify(角色提示)>
  [sandbox=read-only: -s read-only] [sandbox=none: --dangerously-bypass-approvals-and-sandbox]
  [planner: --disable shell_tool -c web_search="disabled"]
  -
```

- 正文写临时文件，通过 stdin 传入。`runProcess` 增加可选的 `stdinPath`。长 diff 走 argv 会超过 Linux 单参数 128 KiB 上限。
- `<codex>` 在 MCP 里取 `codexExecutable`，缺失或在 hook 里用 PATH 上的 `codex`。不加测试专用开关，测试把假 `codex` 放到 PATH 前面。
- 回答是最后一条 `agent_message`。必须出现 `turn.completed` 才算正常结束，否则报未正常结束。空回答报失败。
- 用量按 `input = input_tokens - cached_input_tokens` 记录。
- 角色提示 md 从 pi 版复制到 `src/roles/`，esbuild 用 `--loader:.md=text` 打进包。`developer_instructions` 用 `JSON.stringify` 得到合法的 TOML 字符串。

planner 只关了 shell 和联网，`apply_patch` 有没有关掉没有验证。它只拿到记录文本，提示里写明不用工具。这是已知边界，写进 README。

### 共享角色逻辑

`src/roles/tools.ts` 移植 `ROLES`、`reviewMessage`、`runAndMeter`、`chronicle`、`timeoutAdvice`，`session` 和 `sandbox`、`codex` 由调用方传入。文案与 pi 版相同，去掉提示路径字段。

**史官不用队列。** hook 和 MCP 是不同进程，pi 版的内存队列无效。改成乐观写入：读文档，跑史官，写之前再读一次，内容变了就不写，返回“文档在此期间被改动，未写入，请重新汇报”。这也覆盖 pi 和 Codex 同时写的情况。`writeCwFile` 从 pi 版复制。

### MCP server

`src/adapters/codex/mcp.ts`，打包成 `dist/mcp.js`。手写 stdio 换行分隔 JSON-RPC，不加 SDK 依赖，只需 `initialize`、`tools/list`、`tools/call`、`ping`、`notifications/cancelled`。

- `initialize` 声明 `tools` 和 `experimental: {"codex/sandbox-state": {}}`。
- 每次调用重新读配置，根目录由 `sandboxCwd` 经 `repoToplevel` 得到。`_meta` 缺失时返回错误文本，不猜目录。
- 每个请求一个 `AbortController`，按 request id 存。收到 `notifications/cancelled` 就 abort，由 `runProcess` 终止进程组。stdin 关闭时 abort 全部并退出。看门进程兜底 server 被杀的情况。
- 工具参数与 pi 版一致，含 `timeout_s`。`[router]` 闸门只用于手动调用的 review 和 over_review，与 pi 版相同。`router.ts` 从 pi 版复制。

`.mcp.json`：server 名 `counterweight`，`command: "node"`，`args: ["./dist/mcp.js"]`，`cwd: "."`，`tool_timeout_sec: 1860`，`default_tools_approval_mode: "approve"`，`env_vars: ["CODEX_HOME", "OPENAI_API_KEY"]`。`plugin.json` 加 `"mcpServers": "./.mcp.json"`。

`[router].api_key_env` 指向的变量不在白名单里，闸门会按失败处理，也就是照常审查。这是安全方向的降级，写进 README。

### Stop 流程

```text
配置非法 → 报告，结束
检查（若有）
  失败且 claim(repair)：block，reason=检查报告，结束
runAuto（若开了 review 或 chronicle）
  工作树无改动：跳过
  review 与 over_review 并行
  有发现且 claim(findings)：block，reason=发现，systemMessage=检查报告
  有发现但额度已用：写入 systemMessage，不续跑
  无发现且开了 chronicle：自动汇报
systemMessage 显示所有文字
```

`none`、`ASK:`、空回答都不算发现。自动运行的任何失败只是不产生文字，不改变检查结论，与 pi 版相同。`auto.ts` 从 pi 版复制。

`hooks.json`：`Stop` 超时 7200 秒，够 3570 秒检查加 3600 秒自动运行；每个角色有自己的超时，不需要再加外层预算。`PreToolUse` 超时 1830 秒，给 planner。新增 `UserPromptSubmit`（10 秒）和 `SessionEnd`（3 秒）。hook 变了，`plugin.json` 版本升到 0.2.0，用户需要重新信任。

### PAUSE

`PreToolUse` 在保护通过之后执行，条件：`auto.pause` 生效，没有 `agent_id`（只在根线程），补丁里至少一个路径是 `isSourceEdit`，且 `claim(pause)` 成功。先 claim 再请求，失败也不会反复拦。

`src/adapters/codex/transcript.ts` 把 `transcript_path` 的 rollout JSONL 转成 `TranscriptMessage`：

- `response_item` 的 `message`：`user`、`assistant` 保留，`developer` 丢弃。
- `function_call`、`custom_tool_call`：转成助手的 `toolCall`。
- `function_call_output`、`custom_tool_call_output`：转成 `toolResult`。
- `reasoning` 和其他类型丢弃。解析失败的行跳过。

`renderTranscript`、`plannerMessage`、`pauseReason`、`isSourceEdit` 复用 `pause.ts`（从 pi 版复制）。`transcript_path` 为空、读取失败、planner 失败或超时，一律放行，记 `pause` 事件。成功时 deny，理由是 `pauseReason`。

### 提示

`sessionSection(auto)` 恢复 pi 版的两段角色文字，参数是实际生效的 `[auto]`。`SessionStart` 在 `sandbox = "none"` 时提示“角色子进程没有沙箱”，在 `[auto]` 项因缺模型被关闭时逐项提示。
